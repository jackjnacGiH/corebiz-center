# การปรับความเร็ว CoreBiz Center — 11 กันยายน 2569

## เกณฑ์ประจำสำหรับทุก release

- ถือ `/center/shipping` เป็น critical route และวัดทั้งการเปิดผ่านเมนูในระบบกับ full reload หลังการเปลี่ยนแปลงที่กระทบ `/center`
- ระหว่างหน้าขนส่งกำลังโหลด ห้ามเริ่ม background prefetch รายการสินค้าและลูกค้าทั้งหมดซึ่งไม่ได้ใช้ใน critical path ของหน้านี้
- ตรวจ request count, transferred bytes, console error และเวลาที่รายการขนส่งพร้อมใช้งาน พร้อมเทียบกับค่าก่อนแก้
- หากความช้ามาจาก provider, incident หรือข้อจำกัดของบริการ ให้รายงานตามหลักฐาน ห้ามแก้ด้วยการเพิ่มค่าใช้จ่ายหรือเปลี่ยน architecture ใหญ่โดยไม่ได้รับอนุมัติ

## ขอบเขต

ลดการโหลดโค้ดและข้อมูลซ้ำใน CoreBiz `/center` โดยคงหน้าตา ฟิลด์ ปุ่ม ขั้นตอนการทำงาน สิทธิ์ และเงื่อนไขทางธุรกิจเดิม ไม่เปลี่ยน API ขนส่งหรือฐานข้อมูล และไม่เปลี่ยน storefront

## สิ่งที่ปรับ

- **ขนส่ง:** เริ่มอ่านการตั้งค่าและรายการส่งพร้อมกัน แต่ยังรอการตรวจสิทธิ์ก่อนแสดงข้อมูล ผลค้นหาเก่าไม่ทับคำค้นใหม่ โหลดโค้ดใบปะหน้าเมื่อเข้าฟอร์มและใช้ส่วนแสดง/พิมพ์เดิม
- **กลับเข้าหน้าขนส่ง:** เก็บเฉพาะหน้าแรกที่ไม่มีคำค้นหาไว้ใน memory ของ session เพื่อแสดงทันทีเมื่อกลับเข้ามา ภายใน 10 วินาทีไม่ยิง Edge ซ้ำ และเมื่อข้อมูลเก่ากว่านั้นจะตรวจสิทธิ์ การตั้งค่า และรายการล่าสุดเบื้องหลัง การกดโหลดใหม่ข้าม cache เสมอ และการสร้าง แก้ไข ลบ ส่งจริง ตรวจสถานะ หรือแก้การตั้งค่าขนส่งจะล้าง cache ก่อนและหลังคำขอ
- **ขอบเขตของ cache:** cache แยกตามบัญชีและสิทธิ์ และถูกล้างเมื่อเปลี่ยนบัญชีหรือออกจากระบบ หากผู้ดูแลเปลี่ยนสิทธิ์จากอีก session รายการที่แสดงอยู่เดิมอาจค้างได้ไม่เกิน 10 วินาที การเขียนข้อมูลยังถูกตรวจสิทธิ์ที่ server ทุกครั้ง และปุ่มโหลดใหม่จะตรวจทันที
- **ขนส่งเมื่อซิงก์ล้มเหลว:** ถ้าการตรวจรายการล่าสุดหรือสิทธิ์ล้มเหลว ระบบล้างข้อมูลที่ cache ไว้และแสดงข้อผิดพลาด ไม่เก็บรายการเก่าไว้โดยไม่มีกำหนด ผลตอบกลับของหน้าเดิมไม่สามารถทับผลค้นหาใหม่หรือหน้าที่ผู้ใช้เปิดต่อมาได้
- **เปิดระบบ:** ใช้ `INITIAL_SESSION` เป็นจุดเริ่มอ่าน profile แห่งเดียว ทุกการเปลี่ยน auth ยังคงตรวจสิทธิ์ใหม่ ไม่ข้ามการตรวจสิทธิ์เพื่อแลกความเร็ว
- **ข้อมูลรายการ:** รวม cold load/prefetch ที่กำลังอ่านข้อมูลชุดเดียวกันเป็นคำขอเดียว การกดโหลดใหม่และอ่านหลังบันทึกยังเริ่มคำขอใหม่เสมอ การสลับบัญชีล้างทั้ง cache และคำขอที่ใช้ร่วมกัน
- **อัปเดตสด:** ไม่ถอดและต่อ subscription ทุกครั้งที่ render ในหน้าสินค้า คลัง คำสั่งซื้อ และแดชบอร์ด เมื่อมีหลาย event พร้อมกันให้เริ่มอ่านทันที และอ่านซ้ำหลังจบรอบถ้ามี event ค้างอยู่ ไม่มีการหน่วงด้วย timer
- **ผลตอบกลับ:** เฉพาะรอบโหลดล่าสุดเท่านั้นที่แก้ข้อมูล/ข้อผิดพลาด/สถานะโหลดได้ รวมถึงกรณีข้อมูลใหม่จาก SWR ตอบกลับก่อนคำขอประกอบอื่น
- **ฟอนต์:** หน้าทั่วไปโหลดเฉพาะ Sarabun และ Noto Sans Thai ที่ใช้อยู่ ฟอนต์แต่งภาพโหลดพร้อมหน้า Image Studio ทั้ง 53 ตระกูลและชุดน้ำหนักตรงกับก่อนแก้
- **ส่งออก:** โหลดตัวสร้าง PDF และ ZIP เมื่อกดส่งออก ใช้ข้อมูลและตัวสร้างเดิม พบ URL ฟอนต์ PDF เดิมตอบ 404 ระหว่างทดสอบ จึงเก็บ Sarabun Regular/Bold จาก Google Fonts พร้อม OFL ไว้ในโปรแกรม
- **แสดงตัวเลข:** ใช้ตัวจัดรูปแบบตัวเลข/เงินบาทซ้ำระหว่างแถวในหน้าสินค้าและคลัง โดยคง locale จำนวนทศนิยม และรูปแบบย่อเดิม

## ผลวัดขนาดไฟล์

วัด build ก่อนแก้จาก `e8eb08e` และหลังแก้ด้วย runtime/ตัวเลือกเดียวกัน รวม static imports ของแต่ละหน้า ไม่รวม module ที่โหลดภายหลัง ขนาด gzip เป็นการบีบอัดไฟล์ build เพื่อเปรียบเทียบ ไม่ใช่เวลาโหลดผ่านเครือข่าย

| ส่วนที่วัด | ก่อน | หลัง |
|---|---:|---:|
| JavaScript เริ่มหน้าขนส่ง | 851,581 bytes | 825,689 bytes |
| JavaScript เริ่มหน้าขนส่ง (gzip) | 251,633 bytes | 244,966 bytes |
| JavaScript เริ่มหน้าสินค้า | 2,032,994 bytes | 822,572 bytes |
| JavaScript เริ่มหน้าสินค้า (gzip) | 692,238 bytes | 241,841 bytes |
| JavaScript เริ่มหน้าแต่งภาพ | 857,769 bytes | 791,638 bytes |
| คำขอ stylesheet ฟอนต์ตอนเปิดหน้าทั่วไป | 3 | 1 |
| ตระกูลฟอนต์ใน stylesheet เริ่มต้น | 53 | 2 |

เทียบกับเวอร์ชันก่อนเพิ่ม session cache (`e0ecbcd`) JavaScript เริ่มหน้าขนส่งเพิ่ม 1,778 bytes หรือ 618 bytes เมื่อ gzip เพื่อแลกกับการกลับเข้าหน้ารายการภายใน 10 วินาทีโดยไม่เรียก Edge ซ้ำ และการแสดง cache ก่อนซิงก์เบื้องหลังเมื่อข้อมูลเก่ากว่านั้น

วัดซ้ำได้ด้วย:

```powershell
npm run build --workspace frontend -- --manifest
node scripts/measure-frontend-bundles.mjs
```

## การตรวจสอบ

`node --test tests/*.test.mjs` ผ่าน 201/201 รวม shipping domain/rate/database เดิม และ regression ของ auth, cache, realtime, queue, page loaders และ Shipping component

- การเปิดระบบปกติ: อ่าน profile จาก 2 ครั้งเหลือ 1 ครั้งใน deterministic harness เทียบกับ source เดิม
- cold load และ prefetch ที่ซ้อนกัน: 2 คำขอเหลือ 1 คำขอ
- render 10 รอบ: subscription ชุดเดียว โดยใช้ callback ล่าสุดที่ commit แล้ว
- 100 events ระหว่างการอ่านหนึ่งรอบ: อ่านรอบแรกทันทีและตามอีก 1 รอบ การเปลี่ยนแปลงที่มาระหว่างรอบตามยังทำให้มีรอบถัดไป
- ทดสอบสลับบัญชี ออกจากระบบ callback ที่ตอบช้า force reload, invalidation, ล้มเหลว และ unmount/StrictMode
- TypeScript/Vite build ผ่าน; ESLint ไม่มี error และมี warning เดิม 3 จุดใน CustomerReorder, ProductGroupManagerModal และ Ecommerce
- ทดสอบ browser ในเครื่อง: ดาวน์โหลด PDF ภาษาไทยจริงได้ 1 หน้า A4, ฟอนต์ Kanit/Mali/Poppins แสดงได้ และใบปะหน้า 100 × 150 มม. ยังแยกชื่อผู้ติดต่อหลังชื่อองค์กร

ชุดทดสอบ hook ใช้ scheduler จำลองและคำขอที่ควบคุมเวลาตอบกลับเพื่อพิสูจน์ลำดับข้อมูล ไม่ใช้ผลนี้อ้างเวลา network จริง ต้องตรวจการเปิดหน้า ค้นหา ฟอร์ม และการส่งออกบนเว็บที่ deploy แล้วด้วย
