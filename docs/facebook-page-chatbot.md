# Facebook Page chatbot — jnacP01

The Facebook Page uses the existing CoreBiz product catalog, public knowledge base, and `rag-chat` decision flow. Messenger messages appear under **Facebook** in Omni-Chat; public post comments receive a public answer only when the bot can verify facts from the catalog or public knowledge. Customer-specific, billing, document, and payment requests in comments receive an invitation to use Inbox. Comments do not create CRM leads or quotations.

The `facebook_comment_events` ledger retains comment IDs and delivery status without storing comment text. The webhook stores incoming Messenger messages or comment IDs before acknowledging Meta; a database failure returns HTTP 503 for a retry. Failed asynchronous replies require staff review, because the Graph API may already have published part or all of a reply. Omni-Chat marks these messages for staff rather than sending a duplicate automatically. Images and files are visible to staff, while the bot leaves attachment messages to staff. Messenger staff replies use the standard 24-hour response window and show a failed-delivery marker in Omni-Chat when Graph rejects them.
