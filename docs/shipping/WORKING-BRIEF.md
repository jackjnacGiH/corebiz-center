# Working Brief: สำรวจ API ขนส่งและวางแผนเชื่อม CoreBiz Center

- Status: Confirmed
- Brief ID: 2026-09-08-corebiz-shipping-api
- Updated: 2026-09-08
- ผู้ยืนยัน: Boss jack ยืนยันร่างในบทสนทนานี้

## Outcome

จัดทำเอกสารสำรวจ API ขนส่งและแผนเชื่อมกับ CoreBiz Center เพื่อใช้ตัดสินใจและเตรียมพัฒนาระบบ โดยยังไม่ลงมือพัฒนาฟังก์ชันในรอบนี้

## Context

J NAC ต้องการให้พนักงานส่งสินค้าของบริษัทผ่าน CoreBiz Center รองรับทั้งรายการที่สร้างจากคำสั่งซื้อเดิมและรายการที่สร้างเอง เพราะงานส่งของอาจไม่มีคำสั่งซื้อทุกครั้ง ต้องรวมการเก็บเงินปลายทาง (COD) ไว้ในแผนตั้งแต่ต้น

## Audience / Users

- พนักงาน J NAC ที่ได้รับสิทธิ์จัดส่งสินค้าของบริษัท
- เจ้าของหรือผู้ดูแลที่รับผิดชอบเครดิตและบัญชีรับเงิน COD
- ผู้พัฒนาระบบและผู้ตัดสินใจที่ใช้เอกสารเตรียมการเชื่อม API

## Deliverable

เอกสาร Markdown ภาษาไทยใน `docs/shipping/` พร้อมสรุปผลในแชต ครอบคลุมภาพรวมระบบ คู่มือ API ทั้ง 15 operations ขั้นตอนงานและสิทธิ์ผู้ใช้ แผนเชื่อมข้อมูลกับ CoreBiz และคำถามถึงผู้ให้บริการ

## In Scope

- ตรวจโค้ดและเอกสารของ `jackjnacGiH/corebiz-center` และแหล่งข้อมูลขนส่งที่ผู้ใช้ระบุ
- อธิบาย API ทั้ง 15 operations ที่พบในสเปก รวม authentication ข้อมูลรับเข้า/ตอบกลับ ตัวอย่างที่ล้างข้อมูลอ่อนไหว และข้อจำกัดเท่าที่เอกสารยืนยันได้
- ศึกษาการเช็กราคา สร้างรายการส่ง พิมพ์ใบปะหน้า ติดตามสถานะ ยกเลิก เรียกรถเข้ารับ COD และเครดิต
- วางแผนรายการส่งจากคำสั่งซื้อ CoreBiz และรายการส่งอิสระ
- ระบุจุดเชื่อมข้อมูล สิทธิ์ และช่องว่างที่ต้องพัฒนา โดยแยกข้อเสนอออกจากความสามารถที่มีหลักฐานในระบบเดิม
- ระบุความขัดแย้งในสเปกและข้อมูลที่ต้องขอเพิ่มจากผู้ให้บริการ

## Out of Scope

- แก้โค้ดระบบหรือเปลี่ยนฐานข้อมูล
- Deploy หรือเผยแพร่การเปลี่ยนแปลงขึ้น production
- สร้างรายการส่งจริง เรียกรถจริง หรือยกเลิกรายการจริง
- เติมเครดิต ตั้งค่าบัญชีจริง หรือทำธุรกรรมการเงิน
- เปิดบริการให้ลูกค้าภายนอกสร้างรายการส่งเอง

## Requirements & Decisions

- พนักงานที่ได้รับสิทธิ์สร้างรายการส่งจริงได้เอง โดยไม่ต้องให้หัวหน้าอนุมัติทุกรายการ
- การเติมเครดิตและตั้งค่าบัญชีรับเงิน COD จำกัดเฉพาะเจ้าของหรือผู้ดูแล
- รองรับทั้งส่งจากคำสั่งซื้อและสร้างรายการส่งเอง
- รวม COD ไว้ในแผนตั้งแต่ต้น
- สิทธิ์ข้างต้นเป็นข้อกำหนดของระบบที่จะพัฒนา ไม่ใช่การอนุญาตให้ผู้จัดทำเอกสารทำธุรกรรมจริงในรอบนี้
