# Checklist เปิดใช้งาน PromptSpeed กับ CoreBiz

วันที่ตรวจสถานะ: 10 กันยายน 2026

สเปกอ้างอิง: Open API V3 เวอร์ชัน 3.0.7

เอกสารนี้ใช้ควบคุมการเปิดระบบทีละขั้น ไม่ใช่คำอนุมัติให้สร้างพัสดุ เติมเครดิต หรือเปิด Production

## สถานะปัจจุบัน

| หัวข้อ | สถานะที่ตรวจได้ | ผลต่อการเปิดใช้งาน |
| --- | --- | --- |
| PromptSpeed UAT | Base URL `https://openapi-uat.promptspeed.co.th` ตอบสนอง | ใช้ทดสอบ read และเช็กราคาได้ |
| HMAC | ยืนยันกับ GET ที่ทดสอบและ POST JSON ของ check-price: ใช้ `api_key` เป็น App ID, timestamp เป็น milliseconds และ HMAC-SHA256 แบบ hex | ยังไม่ถือว่ารับรอง multipart, Unicode/array ทุกกรณี หรืออายุลายเซ็น |
| Merchant | มี Merchant UAT ของ J NAC แล้ว | เก็บรหัส Merchant ในค่าฝั่ง server/หน้าตั้งค่า ไม่เขียนรหัสหรือกุญแจลงเอกสาร |
| รายชื่อและการผูกบริการ | Merchant UAT ถูกผูกไว้ 11 บริการ และ `GET /api/v3/carrier/list` ส่งกลับ 11 บริการ | เป็นสถานะ UAT ต้องยืนยันเงื่อนไขของแต่ละบริการก่อน Production |
| การเรียกเก็บเงิน | CoreBiz UAT ตั้งเป็น `prepaid` | การสร้างพัสดุต้องมี Wallet เพียงพอตามเงื่อนไข PromptSpeed |
| ผู้ส่ง | บันทึกเบอร์โทรและอีเมลที่ API ต้องใช้แล้ว | ค่าจริงอยู่ในระบบและไม่เผยแพร่ในเอกสาร |
| เช็กราคา | หน้า CoreBiz ทดสอบกล่อง 20 × 10 × 30 ซม. 1,200 กรัม จาก 10280 ไป 10280 และได้ราคา 11 บริการ โดยไม่ได้บันทึกร่าง | เป็นราคา UAT สำหรับทดสอบ ไม่ใช่ราคาที่รับรองสำหรับส่งจริง |
| Wallet | สถานะ Verified/Ready แต่ยอดที่ตรวจเป็น `0.00` | บัญชีพร้อมรับรายการเติมเงิน แต่ยังไม่มีเงินสำหรับพิสูจน์การตัดยอดแบบ prepaid |
| Credit | ยังอยู่ Waiting for document/Processing | ยังใช้วงเงินเครดิตเป็นหลักฐานเปิดสร้างพัสดุไม่ได้ |
| COD | บัญชีแสดง Active แต่ carrier mapping และ bank mapping เป็น 0 | ยังเปิดส่ง COD หรือรับรองการโอนเงิน COD ไม่ได้ |
| การสร้าง/ยกเลิก/เติมเงิน | `PROMPTSPEED_MUTATIONS_ENABLED=false` | CoreBiz ไม่ส่งคำขอที่อาจสร้างรายการหรือกระทบเงิน |
| Webhook | ยังปิดรับและยังไม่มีวิธียืนยันผู้ส่งจากสเปก | ยังรับรองสถานะพัสดุ ราคาเปลี่ยน หรือ pickup callback แบบอัตโนมัติไม่ได้ |
| Pickup | method และ response ID ยังขัดแย้ง/ไม่ครบ และยังไม่มี `warehouse_no` ที่ยืนยันสำหรับ J NAC | ยังไม่เปิดเรียกรถหรือยกเลิกรถเข้ารับ |

## สิ่งที่ CoreBiz ทำได้แล้ว

- [x] สร้าง แก้ไข และลบร่างภายใน โดยยังไม่สร้างพัสดุกับผู้ให้บริการ
- [x] สร้างร่างจากคำสั่งซื้อหรือสร้างรายการส่งอิสระ
- [x] ค้นผู้รับ สินค้า และกรอกข้อมูลกล่อง/น้ำหนัก
- [x] เรียกรายชื่อบริการและเปรียบเทียบราคา UAT ก่อนเลือกขนส่ง
- [x] แยก secret ไว้ฝั่ง server และตรวจสิทธิ์ผู้ใช้ก่อนเรียก API
- [x] ปิด mutation เป็นค่าเริ่มต้น เพื่อกันการสร้างพัสดุหรือหักเงินโดยไม่ตั้งใจ
- [ ] ทดสอบสร้างพัสดุ UAT แบบไม่เก็บเงินปลายทาง
- [ ] รับเลข Tracking และพิมพ์ใบปะหน้าจาก PromptSpeed
- [ ] ตรวจสถานะ ยกเลิก และกู้ผลเมื่อ request timeout แบบไม่สร้างรายการซ้ำ
- [ ] รับ webhook ที่ตรวจลายเซ็น ป้องกัน replay และประมวลผลซ้ำได้อย่างปลอดภัย
- [ ] เรียกรถเข้ารับและยกเลิก pickup ด้วย ID ที่ผู้ให้บริการยืนยัน

## สิ่งที่ PromptSpeed ต้องเปิดหรือยืนยัน

- [x] ผูกบริการขนส่ง 11 รายการกับ Merchant UAT
- [ ] ยืนยัน capability ของแต่ละบริการ เช่น COD, pickup, น้ำหนักสูงสุด พื้นที่ให้บริการ และสิทธิ์สร้างพัสดุใน Production
- [ ] ยืนยันขั้นตอนเติม Wallet สำหรับบัญชี `prepaid` ที่ Verified/Ready; เอกสาร Credit ที่ยัง Waiting for document/Processing เป็นเส้นทางสำรองจนกว่าจะได้รับอนุมัติ
- [ ] แจ้งยอดใช้ได้จริงหรือวงเงินเครดิต และอธิบายว่าค่าขนส่งถูกตัดเมื่อใด รวมวิธีคืนยอดหลังยกเลิก
- [ ] ยืนยัน method ที่ใช้งานจริงสำหรับ check-price, เติม Wallet, สร้าง pickup และยกเลิก pickup เพราะ path ใน YAML กับตาราง environment ขัดกัน
- [ ] ยืนยัน Production base URL ทุก operation โดยเฉพาะ list shipment ซึ่งเอกสารอ้าง host ต่างจาก operation อื่น
- [ ] ให้ HMAC test vector สำหรับ GET, JSON, multipart และข้อมูล Unicode/array รวม clock skew และอายุลายเซ็น
- [ ] ให้ contract สำหรับ idempotency/retry และวิธีค้นรายการจาก `external_id` เมื่อสร้างพัสดุ timeout ก่อนทราบ Tracking
- [ ] ให้ขั้นตอนลงทะเบียน webhook, signature/header, secret rotation, replay window, retry และตัวอย่าง acknowledgment
- [ ] ให้ `warehouse_no` ของจุดรับ J NAC วิธีสร้าง pickup, รูปแบบ pickup ID และ mapping กับ `ticket_pickup_id` ใน callback
- [ ] ยืนยันขั้นตอนบัญชี COD, carrier ที่รองรับ, รอบโอน และหลักฐาน settlement แยกจากสถานะ delivered

## จุดที่ Boss jack ต้องยืนยัน

- [ ] เลือกว่าจะเริ่มด้วย UAT non-COD เท่านั้น หรือรวม COD ในรอบทดสอบหลัง PromptSpeed เปิดบัญชีแล้ว
- [ ] ยืนยันผู้มีสิทธิ์สร้างพัสดุ ยกเลิกพัสดุ และเรียกรถ; การเติมเครดิตและจัดการ COD จำกัด owner/admin ตาม Working Brief
- [ ] ยืนยันจุดรับพัสดุ ผู้ติดต่อ เวลาทำการ และจำนวนพัสดุโดยประมาณสำหรับ pickup
- [ ] อนุมัติ carrier กลุ่มแรกสำหรับ pilot หลัง PromptSpeed ยืนยันสิทธิ์ Merchant
- [ ] **ก่อนเติมเครดิตทุกครั้ง:** ยืนยัน environment, จำนวนเงิน, บัญชี/หลักฐานการโอน และผู้ดำเนินการเป็นรายการสุดท้ายก่อนส่งคำขอ ห้ามใช้ยอดตัวอย่างหรือเติมอัตโนมัติ

## ลำดับเปิดใช้งาน

### 1. ปิดช่องว่างของบัญชี

- [x] Merchant UAT ผูก carrier 11 บริการแล้ว
- [x] ตั้ง billing mode UAT เป็น `prepaid`
- [x] บันทึกเบอร์โทรและอีเมลผู้ส่งที่ API ต้องใช้ โดยไม่เผยแพร่ค่าจริงในเอกสาร
- [ ] เติม Wallet ที่ Verified/Ready หลัง Boss jack ยืนยันจำนวนเงิน หรือรอ Credit ผ่านการอนุมัติก่อนเปลี่ยนโหมดในอนาคต
- [ ] ตรวจยอด/วงเงินและสิทธิ์ใน Portal ซ้ำ

**ผ่านขั้นนี้เมื่อ:** ผู้ให้บริการยืนยันเป็นลายลักษณ์อักษรว่าบัญชี UAT สร้างพัสดุทดสอบได้โดยไม่คิดเงินจริง หรือแจ้งค่าใช้จ่ายชัดเจนและ Boss jack อนุมัติแล้ว พร้อมมียอด Wallet/วงเงินที่ตรวจสอบได้

### 2. ทดสอบ mutation UAT แบบจำกัด

- [ ] ใช้รายการสังเคราะห์หนึ่งกล่อง แบบ non-COD และ carrier เดียว
- [ ] เปิด mutation เฉพาะช่วงทดสอบโดยผู้ดูแล แล้วสร้างพัสดุหนึ่งครั้ง
- [ ] ตรวจ Tracking, charge, Wallet/วงเงิน และ audit ก่อน/หลัง
- [ ] ทดสอบพิมพ์ใบปะหน้าจาก Tracking เดิม ไม่สร้างพัสดุซ้ำ
- [ ] ทดสอบ refresh status และยกเลิกตามสถานะที่ PromptSpeed อนุญาต
- [ ] ปิด mutation ทันทีเมื่อผลไม่ตรงหรือไม่ทราบผลหลัง timeout

**ผ่านขั้นนี้เมื่อ:** ได้ Tracking จริงใน UAT, ยอดถูกต้อง, พิมพ์ได้ และการกดซ้ำ/timeout ไม่สร้างพัสดุหรือหักยอดซ้ำ

### 3. เปิด webhook และ pickup

- [ ] ลงทะเบียน URL แยก UAT/Production และตรวจลายเซ็นก่อนรับ event
- [ ] ทดสอบ event ซ้ำ ย้อนลำดับ และ callback ที่มาก่อน create response
- [ ] ลงทะเบียนคลัง/`warehouse_no` และทดสอบ pickup หนึ่งรายการ
- [ ] ตรวจ pickup ID, callback ID, การยกเลิก และข้อมูลคนขับตามนโยบายเก็บข้อมูล

**ผ่านขั้นนี้เมื่อ:** callback ปลอมถูกปฏิเสธ event ซ้ำไม่ทำให้สถานะหรือเงินซ้ำ และ pickup สร้าง/ยกเลิกได้ด้วย ID ชุดเดียวกัน

### 4. ทดสอบ COD และเตรียม Production pilot

- [ ] PromptSpeed อนุมัติบัญชี COD และแจ้ง settlement contract
- [ ] ทดสอบ COD ด้วยยอดที่อนุมัติและกระทบยอดกับรายงานผู้ให้บริการ
- [ ] ยืนยันว่า delivered ไม่ถูกใช้แทน COD paid
- [ ] ติดตั้งกุญแจ Production แยกจาก UAT และเริ่ม carrier/พนักงาน/คลังแบบจำกัด
- [ ] ตรวจราคา Tracking label webhook ยกเลิก pickup Wallet/Credit และ COD ครบก่อนขยายผู้ใช้

**ผ่านขั้นนี้เมื่อ:** Boss jack อนุมัติ pilot หลังเห็นผล UAT และผู้ดูแลยืนยันยอดเงิน/สัญญาที่มีผลจริง

## เงื่อนไขหยุด

ให้คง `PROMPTSPEED_MUTATIONS_ENABLED=false` เมื่อเกิดข้อใดข้อหนึ่ง:

- PromptSpeed ยังไม่ยืนยันสิทธิ์สร้างพัสดุของ carrier ที่ผูกกับ Merchant
- Wallet ยังเป็น 0.00 และ Credit ยังไม่อนุมัติ หรือยอด/วงเงินไม่ชัดเจน
- ไม่ทราบผลหลัง create/cancel/pickup timeout และไม่มีวิธีกู้จากผู้ให้บริการ
- method, base URL, HMAC หรือ response ที่ได้รับต่างจาก contract ที่ยืนยัน
- webhook ยังยืนยันผู้ส่งหรือกัน replay ไม่ได้
- การเติมเครดิตยังไม่ได้รับคำยืนยันจำนวนเงินจาก Boss jack

รายละเอียด endpoint และข้อขัดแย้งอยู่ใน [คู่มือ API](API_REFERENCE.md), สถานะ UAT อยู่ใน [UAT_CONNECTION.md](UAT_CONNECTION.md) และคำถามที่ต้องส่งให้ผู้ให้บริการอยู่ใน [QUESTIONS.md](QUESTIONS.md)
