# ระบบขนส่งสำหรับ CoreBiz Center

สถานะ: ติดตั้งโมดูลฐานบน CoreBiz production แล้ว และกำลังส่งมอบรอบปรับปรุงฟอร์มผู้รับ/ขนส่ง การเรียก PromptSpeed จริงยังปิดไว้จนกว่าจะยืนยัน credential, base URL, สเปกการลงลายเซ็น และรูปแบบเรียกเก็บเงิน อ่าน [คู่มือส่งต่อและข้อจำกัด](IMPLEMENTATION.md) ก่อนเปิดใช้ธุรกรรมขนส่ง

วันที่สำรวจ: 8 กันยายน 2026 | สเปก: Open API V3 เวอร์ชัน 3.0.7

## ข้อสรุปสำหรับตัดสินใจ

CoreBiz มีหน้า `/center/shipping`, ตาราง/RLS และ Edge Function `shipping-api` สำหรับงานภายในแล้ว สร้างร่างจากคำสั่งซื้อหรือรายการอิสระ ดึงสินค้า/ผู้รับ ค้นผู้รับเดิม เติมที่อยู่จากรหัสไปรษณีย์ เลือกขนส่งพร้อมโลโก้ พิมพ์ลาเบล J NAC และคัดลอกลิงก์ติดตามได้ สถานะพัสดุแยกจากสถานะคำสั่งซื้อเพื่อไม่กระทบ stock หรือ COD โดยอัตโนมัติ

สเปกที่ได้รับมี 15 operations: เรียกผู้ให้บริการ 12 operations และรับ webhook 3 operations โค้ด adapter รองรับเช็กราคา สร้างพัสดุ ขอใบปะหน้า และดึงสถานะแบบ fail-closed แต่ปุ่มที่เรียก provider จะยังปิดเมื่อ secret/flag หรือข้อมูลบัญชียังไม่พร้อม

ขอบเขตที่ Boss jack ยืนยันคือพนักงาน J NAC ส่งสินค้าของบริษัท สร้างจากคำสั่งซื้อหรือสร้างเองได้ รวม COD ตั้งแต่ต้น พนักงานที่ได้รับสิทธิ์สร้างรายการส่งได้เอง เจ้าของ/ผู้ดูแลเท่านั้นที่เติมเครดิตและจัดการบัญชีรับเงิน COD

ประเด็นที่ต้องยืนยันก่อนเชื่อมบริการจริง:

1. สเปกกับคำอธิบายใช้ HTTP method ไม่ตรงกันใน 4 operations และ URL รายการส่งต่างจากบริการอื่น
2. ยังไม่มีรายละเอียดวิธียืนยัน webhook, การส่งซ้ำ และการกู้สถานะหลัง request timeout ที่เพียงพอ
3. มีช่อง `cod_account` แต่ไม่มี API จัดการบัญชี COD หรือรายงานโอนเงิน COD ใน 15 operations นี้
4. ต้องยืนยันรูปแบบบัญชีวางบิล/เติมเครดิต ไม่กำหนดว่า Wallet ต้องเป็นเงื่อนไขก่อนส่งเสมอ
5. CoreBiz มี trigger เปลี่ยนสต็อกตามสถานะคำสั่งซื้อ การยกเลิกพัสดุต้องไม่ไปยกเลิกคำสั่งซื้อหรือคืนสต็อกเอง
