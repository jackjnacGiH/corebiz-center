# การเชื่อมต่อ PromptSpeed UAT

วันที่ตรวจ: 9 กันยายน 2026

## สถานะที่ยืนยันแล้ว

- เข้าบัญชีบริษัทใน `https://portal-uat.promptspeed.co.th/login` ได้ บัญชีเป็น Partner และเปิดใช้งาน
- ก่อนตั้งค่าพบว่า Partner ยังไม่มี Merchant จึงสร้าง `J NAC CoreBiz UAT` ด้วย API สำหรับทดสอบ CoreBiz โดยใช้ข้อมูลบริษัทที่ผู้ใช้ให้และข้อมูลผู้ส่งในระบบ
- Partner token ใช้เป็น Bearer สำหรับสร้าง Merchant ส่วน `api_key` และ `api_secret` ที่ได้รับจาก Merchant ใช้กับการลงลายเซ็น HMAC โดยนำ `api_key` ไปใช้เป็น `app_id`
- ติดตั้งเฉพาะกุญแจ UAT ใน Supabase Secrets และบันทึกรหัส Merchant ในหน้าตั้งค่าขนส่งของ CoreBiz มีผู้ใช้ที่บันทึกการเปลี่ยนแปลงกำกับ
- รหัสผ่าน, Partner token, App ID และ Secret ไม่อยู่ใน Git หรือเอกสารนี้

## ผลทดสอบ

| สิ่งที่ทดสอบ | ผล | ขอบเขต |
| --- | --- | --- |
| `POST /api/v3/merchant` ด้วย Bearer ของ Partner | HTTP 201 ได้ Merchant และกุญแจ | สร้างบัญชีร้านค้าทดสอบ ไม่มีการสร้างพัสดุ |
| `GET /api/v3/carrier/list` ด้วย HMAC | HTTP 200 ได้บริการ 11 รายการ | บริการที่บัญชี UAT นี้ส่งกลับ |
| `GET /api/v3/shipment/check-address` ด้วย HMAC | HTTP 200 ได้พื้นที่ 6 รายการ | `postcode=10280`, `carrier_code=FLASH_EXPRESS_SPEED`, `limit=100`; ตรงกับผลค้นหาใน Portal |
| `POST /api/v3/shipment/check-price` ด้วย HMAC | HTTP 200 ได้ราคา Flash และ Best ในคำขอเดียว | สมุทรปราการ 10280 ไปกรุงเทพมหานคร 10330; กว้าง 20 สูง 10 ยาว 30 ซม.; น้ำหนัก 1,200 กรัม |
| `check-price` โดยส่งเฉพาะพื้นที่และกล่อง | HTTP 200 ได้ราคา EMS ใน UAT | 10280 ไป 10330; กว้าง 10 สูง 10 ยาว 15 ซม.; น้ำหนัก 200 กรัม; ไม่ส่งข้อมูลผู้ติดต่อ สินค้า หรือ COD |
| เช็กราคาจากหน้า CoreBiz ผ่าน `shipping-api` | ได้ชื่อบริการ ยอดประเมิน และระยะเวลา | ร่างทดสอบใหม่ที่ผูก Merchant UAT; Flash; ยังเป็นสถานะร่าง |
| ปุ่มสร้างพัสดุ | ปิดใช้งาน | ไม่มีเลข Tracking และยังไม่ได้ส่งคำสั่งสร้างพัสดุ |

ผลข้างต้นยืนยันการใช้ `api_key` เป็น App ID, timestamp หน่วย milliseconds, HMAC-SHA256 แบบ hex และ POST JSON ของ check-price สำหรับคำขอที่ทดสอบ ไม่ได้ยืนยันอายุลายเซ็น, clock skew, การ sign multipart หรือ operations อื่นทั้งหมด

## ค่าที่ตั้งบนเซิร์ฟเวอร์

| ค่า | สถานะ |
| --- | --- |
| `shipping_settings.environment` | `uat` |
| `shipping_settings.merchant_code` | ผูก Merchant ทดสอบแล้ว ดูรหัสในหน้าตั้งค่าขนส่ง |
| `shipping_settings.billing_mode` | `unconfirmed` |
| `PROMPTSPEED_UAT_APP_ID` / `PROMPTSPEED_UAT_SECRET` | ติดตั้งแล้ว เก็บเฉพาะฝั่งเซิร์ฟเวอร์ |
| `PROMPTSPEED_SPEC_CONFIRMED` | `true` สำหรับขอบเขต UAT ที่ทดสอบด้านบน ไม่ใช่การรับรองสเปกทั้งชุด |
| `PROMPTSPEED_READS_ENABLED` | `true` |
| `PROMPTSPEED_MUTATIONS_ENABLED` | `false` |
| กุญแจ Production | ไม่ได้ติดตั้งในรอบนี้ |

Base URL ที่ทดสอบ: `https://openapi-uat.promptspeed.co.th` โค้ด provider เดิมผ่านการทดสอบได้โดยไม่ต้องเปลี่ยน Edge Function `shipping-api` รุ่น 3

## ผลตรวจหน้าจัดการพื้นที่บริการ

ตรวจหน้า [Areas Management](https://portal-uat.promptspeed.co.th/mybackend/settinglogistics/areasmanagement/index) ด้วยบัญชี Partner ของบริษัทวันที่ 9 กันยายน 2026:

- มีข้อมูลพื้นที่ของ 11 บริการและเครื่องหมายถูกในคอลัมน์ API ครบทั้ง 11 แถว ข้อมูลนี้เป็นของ UAT ไม่ได้ยืนยันพื้นที่ Production
- ตัวอย่าง Flash แสดง 7,657 รายการพื้นที่, Remote area 358 รายการ และ Tourism area 94 รายการ ตัวเลขคือจำนวนรายการในหน้าจอ ไม่ใช่จำนวนรหัสไปรษณีย์ที่ไม่ซ้ำ
- เปิดรายละเอียด Flash แล้วค้น `10280` ได้สมุทรปราการ / เมืองสมุทรปราการ 6 ตำบล: ท้ายบ้าน, บางปูใหม่, แพรกษา, บางปู, ท้ายบ้านใหม่ และแพรกษาใหม่ ทั้ง 6 แถวแสดง `-` ในคอลัมน์ Remote, Tourism และ Island
- API check-address ส่งกลับ `success`, `count`, `data`, `request_id` และแต่ละรายการใน `data` มี `state`, `city`, `county`, `zipcode` ผลพื้นที่ตรงกับ Portal ทั้ง 6 รายการ แต่ไม่มีสถานะ Remote/Tourism/Island ใน response ที่ตรวจ จึงห้ามใช้เพียงผลนี้ตัดสินว่าไม่มีค่าพื้นที่พิเศษ
- ปุ่ม Download template, Export File, Import File และลบแถวในบัญชีที่ตรวจถูกปิด ไม่มีการเปลี่ยนสิทธิ์หรือข้ามข้อจำกัดของ Portal
- รอบตรวจนี้ใช้การค้นหาใน Portal และ GET API เท่านั้น ไม่แก้พื้นที่ ราคา เครดิต บัญชี COD หรือเปิดการสร้างพัสดุ ไม่จำเป็นต้องเพิ่มพื้นที่ 10280 เพราะมีอยู่แล้ว
- ฟอร์มที่อยู่ CoreBiz ยังใช้ฐานเดียวกับหน้าลูกค้า ผลตรวจนี้ไม่ได้เปลี่ยนฐานที่อยู่ของ CoreBiz เป็นข้อมูลจากผู้ให้บริการ

## วิธีทดลองเช็กราคาใน CoreBiz

1. เปิดหน้า **ขนส่ง** แล้วกด **สร้างรายการส่ง** เพื่อให้ร่างผูกกับ Merchant ปัจจุบัน
2. กรอกพื้นที่ผู้ส่งและผู้รับ: จังหวัด อำเภอ/เขต ตำบล/แขวง และรหัสไปรษณีย์ 5 หลัก
3. ระบุจำนวนกล่อง กรอกกว้าง สูง ยาวเป็นเซนติเมตร และน้ำหนักรวมเป็นกรัมแยกแต่ละกล่อง ทุกค่าต้องมากกว่า 0
4. กด **เปรียบเทียบราคาขนส่ง** ก่อนเลือกขนส่งหรือบันทึกร่างได้ ระบบดึงบริการที่บัญชีรองรับแล้วส่งหลายบริการใน `carriers_code`
5. เปรียบเทียบราคารวมทุกกล่อง เปิดดูราคาแยกกล่อง แล้วเลือกขนส่งและบันทึกร่าง รายที่ให้ราคาไม่ครบทุกกล่องจะไม่ถูกจัดเป็นราคาต่ำสุด ดู [คู่มือใช้งาน](USAGE.md)

การเช็กราคาไม่บังคับน้ำหนักรายสินค้า เบอร์โทร อีเมล หรือบัญชี COD ที่อนุมัติแล้ว ระบบส่งเฉพาะพื้นที่และข้อมูลกล่องไปขอราคา ส่วนการสร้างพัสดุยังตรวจข้อมูลผู้ส่ง ผู้รับ สินค้า และ COD ตามเงื่อนไขเดิม หากข้อมูลสำหรับเช็กราคายังไม่ครบ หน้าฟอร์มจะแสดงรายการช่องที่ต้องเติมข้างปุ่ม

การบันทึกร่างหรือเช็กราคาสำเร็จยังไม่ทำให้มีเลข Tracking เลขจะได้รับเมื่อผู้ให้บริการสร้างพัสดุสำเร็จเท่านั้น บาร์โค้ดเลข `SHP-...` บนร่างเป็นเลขอ้างอิงภายใน ไม่ใช่เลขติดตามจากขนส่ง

**ราคาและระยะเวลา UAT ใช้ทดสอบเท่านั้น ไม่ใช่ข้อเสนอราคาส่งจริง** หน้าเว็บระบุ UAT ทั้งบริเวณสถานะและผลราคา

ร่างที่สร้างก่อนผูก Merchant ยังอยู่ในบัญชีเดิม ระบบจะตอบ `account_changed` หากนำไปเรียกขนส่ง ให้สร้างร่างใหม่เพื่อทดสอบ ไม่ย้ายบัญชีของร่างเก่าหรือแก้ประวัติย้อนหลัง

## สิ่งที่ยังไม่ได้เปิด

- การสร้างพัสดุ ยกเลิกพัสดุ เรียกรถ เติมเงิน เปลี่ยนโหมดวางบิล และบัญชีรับ COD
- การเชื่อม Production ต้องใช้กุญแจ Production ที่ถูกต้องและยืนยันการคิดค่าบริการกับผู้ดูแลก่อน
- การพิมพ์ใบปะหน้าจากผู้ให้บริการ การดึงสถานะพัสดุจริง และ webhook ยังต้องทดสอบแยกต่างหาก
- หน้าเปรียบเทียบใช้รายชื่อจาก API บัญชีปัจจุบัน; โลโก้/ชื่อแสดงผลบางส่วนใช้ asset ที่เตรียมไว้ การให้ราคา UAT ไม่ใช่การยืนยันบริการ Production
- ห้ามนำสถานะ `SPEC_CONFIRMED` ของรอบนี้ไปตีความว่า production, COD, webhook, retry หรือ operations ที่ไม่ได้ทดสอบพร้อมใช้งานแล้ว ดู [QUESTIONS.md](QUESTIONS.md) สำหรับประเด็นคงค้าง
